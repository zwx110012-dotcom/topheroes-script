# topheroes脚本

这个项目从可见游戏窗口截图读取状态，使用 OpenCV 模板匹配定位按钮，通过鼠标点击操作。游戏状态只来自像素；代码没有进程内存读取、进程代码注入、游戏接口或辅助功能树读取。窗口标题、位置、尺寸和前台状态通过 Windows 窗口接口确定。

## 可视化 EXE

从本仓库的 [Releases 下载页](../../releases) 下载 `TopHeroesHelper.exe`，或者按下文从源码构建到 `dist/`。直接打开 EXE，无需安装 Python。界面提供：

- 游戏窗口与尺寸检查、1到3队的目标数量、启动倒计时。
- 「预览识别」显示游戏截图、匹配框与置信度，不点击游戏。
- 识别前移开游戏鼠标指针；识别超时显示最高得分并保存带匹配框的诊断截图。
- 默认勾选「持续采集」：读左侧时间、等待返程、识别空闲后补队。取消勾选则执行单轮。
- 「停止」与全局 F8 停止；等待过程可中断，退出会等当前鼠标动作释放后关闭。
- 截图、三队状态与倒计时、下次检查闹钟、累计补队次数和运行日志。
- 游戏客户区固定为1600×900，启动时与运行中自动恢复尺寸。

开始时界面自动最小化并切回游戏；结束或停止后恢复界面。游戏应停留在城内或世界地图，展开队列列表并关闭弹窗。切换离开游戏时，脚本停止点击。

日志和界面设置保存在 `%LOCALAPPDATA%\TopHeroesHelper`；「打开日志」可查看具体文件。
识别失败的截图保存在同目录下的 `diagnostics` 文件夹，具体路径写入日志。

### 标准窗口尺寸

采集和识别预览都以 **1600×900 游戏客户区** 为标准，标题栏和边框另计。尺寸定义在 `gather_crystal.yaml` 的 `window_size` 中。恢复使用 Windows 窗口尺寸接口，只涉及窗口管理，不访问游戏内存。

启动时先恢复尺寸；运行中发现误拖边框或最大化改变了尺寸，会暂停点击、恢复窗口、等布局稳定，再从新截图识别。如果尺寸在识别与点击之间改变，该次点击取消，重新定位按钮；不会沿用旧坐标。出发已经点击过时仍先确认队列变化，不会重新派队。

F8 可取消恢复过程。切换离开游戏、屏幕可用区域装不下标准窗口、或者窗口持续改变而无法稳定时，会停止并报告原因。脚本不会修改显示器分辨率。

从源码启动：`python topheroes_gui.py`。重新构建单文件 EXE：

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements-build.txt
.\build_exe.ps1
```

## 6级红水晶采集

`gather_crystal.yaml` 已配置用户演示的流程，`templates/` 中包含识别用的真实截图裁片：

1. 从城内点击右下角世界图标；如果已经在世界地图则继续。
2. 识别空闲队列，点击左下角搜索、资源采集、红水晶采集点。
3. 从图像确认6级。若当前不是6级，逐次点减号直至等级标签不再变化，再逐次点加号，直到匹配6级图像。调整次数有上限。
4. 点击搜索，等待2秒并识别采集按钮，再识别并点击出发。
5. 确认返回世界地图、出发按钮消失，并且可用队伍变为在外状态，计入一次派队。
6. 默认持续监测，直到按F8停止。只有单轮模式会在派出设定数量后结束。

### 持续采集与返程闹钟

队伍栏由「队列」文字定位。英雄头像不参与状态判断；只匹配头像右下角小圆图标的内部，避免头像变化影响结果。回转箭头表示返程；镐子配合右侧快进按钮表示前往采集点，配合召回按钮表示正在采集。旁边的 `HH:MM:SS` 使用真实游戏字体数字模板识别，不依赖在线OCR。数字保留原字体比例、轻度平滑后匹配，并过滤半透明栏后的背景小亮点。

先补足目标在外队伍数，随后按最早倒计时安排检查；最长30秒复核一次，在归零前1秒醒来。归零时继续读取返程图标和新的返程时间。只有连续三帧确认「空闲」才派队，数字无法确认时每2秒复核。倒计时只决定检查时间，不授权点击。

出征面板会隐藏左侧队伍栏，所以打开面板前记录空闲或正在返程的队伍，出发后确认其中一队变为行军/采集；另一队同时回城也不会把成功派队误判为失败。确认失败时停止，不重复点出发。

目标数包含采集、行军和返程中的队伍；已有队伍不会被召回，也无法确认已有采集队的资源类型。返程和出发路程期间不能保证三队同时挖矿，脚本的目标是空闲后及时补充6级红水晶采集。游戏必须保持前台；离开游戏会在下次检查时停止，不自动抢回焦点。

## 采集与配置

1. 打开游戏并保持窗口可见，运行 `.venv\Scripts\python top_heroes.py windows` 查找标题。
2. 运行 `.venv\Scripts\python top_heroes.py capture --title "Top Heroes" --output captures/home.png` 保存窗口客户区截图。
3. 用任意图片编辑器从截图中裁剪按钮和进入页面后的独特标志，存入 `templates/`。裁剪应紧贴图标，避开动态数字、倒计时和半透明特效。
4. 复制 `workflow.example.yaml` 为 `workflow.yaml`，按实际任务顺序配置每一步的 `target` 和点击后的 `after.template`。模板路径相对于配置文件。
5. 先运行 `.venv\Scripts\python top_heroes.py check --config workflow.yaml`，检查模板是否都能读取。
6. 运行 `.venv\Scripts\python top_heroes.py run --config workflow.yaml` 预览匹配位置和置信度。确认正确后，追加 `--execute` 才会点击。

通用 `run` 命令的 `after` 是必填的视觉确认条件。找不到按钮、确认画面未出现、窗口尺寸改变或窗口不在前台时脚本会停止。每次运行最多执行配置里的步骤一次。

窗口必须位于屏幕可见区域，不能最小化或被别的窗口遮挡。采集流程支持配置范围内的多尺度匹配；模板来自同一UI大小的截图时最可靠。动画、换皮肤或大幅缩放仍可能导致识别失败。
